## 1. 개요

### 1.1 배경
하루 단위로 해야 할 일을 빠르게 적고, 완료 여부를 체크하며, 오늘 얼마나 진행했는지 한눈에 볼 수 있는 가벼운 웹페이지가 필요하다. 복잡한 프로젝트 관리 도구가 아니라 **"오늘"에 집중하는 단일 페이지 도구**를 목표로 한다.

### 1.2 목표
- 3초 안에 할일을 추가할 수 있다.
- 오늘의 진행률(완료/전체)을 즉시 확인할 수 있다.
- 브라우저를 닫았다 열어도 데이터가 유지된다.
- 별도 설치·회원가입 없이 정적 파일만으로 동작한다.

### 1.3 비목표 (Out of Scope, v1)
- 회원가입/로그인, 서버 동기화, 다중 기기 공유
- 반복 일정, 캘린더 연동, 알림(푸시)
- 협업(다른 사용자와 공유)

## 4. 기능 요구사항

### 4.1 할일 추가 (FR-01)
- 상단 입력창에 텍스트 입력 후 **Enter** 또는 **추가 버튼**으로 등록.
- 공백만 있는 입력은 무시하고 입력창을 흔드는 등 가벼운 피드백.
- 최대 길이 100자. 초과 시 입력 제한.
- 새 항목은 목록 **맨 위**(또는 미완료 그룹의 맨 아래 — 결정 필요, §10 참고)에 추가.
- 추가 후 입력창은 비워지고 포커스 유지.

### 4.2 완료 토글 (FR-02)
- 각 항목 좌측 체크박스 클릭 시 완료/미완료 토글.
- 완료 항목은 취소선 + 흐린 색상으로 표시.
- 완료 시각(`completedAt`) 기록.

### 4.3 삭제 (FR-03)
- 항목에 마우스를 올리면(모바일은 항상) 삭제 버튼 노출.
- 삭제 직후 5초간 **"실행 취소"** 토스트 제공 (확인 다이얼로그 대신).

### 4.4 수정 (FR-04)
- 텍스트 더블클릭(모바일: 길게 누르기) → 인라인 편집 모드.
- Enter 저장, Esc 취소, 포커스 이탈 시 저장.
- 빈 문자열로 저장 시 해당 항목 삭제.

### 4.5 필터 (FR-05)
- 탭: `전체` / `진행 중` / `완료`.
- 선택된 필터는 URL 해시(`#/active` 등)에 반영해 새로고침 후에도 유지.

### 4.6 진행률 표시 (FR-06)
- 헤더에 오늘 날짜(예: `2026년 11월 2일 (월)`) 표시.
- 진행률 바 + 텍스트 `완료 3 / 전체 5 (60%)`.
- 모두 완료 시 축하 메시지 표시 (예: "오늘 할 일을 모두 끝냈어요 🎉").
- 할일이 0개면 빈 상태 안내 문구 표시.

### 4.7 완료 항목 일괄 삭제 (FR-07)
- 하단에 `완료 항목 지우기` 버튼. 완료 항목이 없으면 비활성화.

### 4.8 데이터 저장 (FR-08)
- `localStorage`에 저장. 모든 변경 시 즉시 저장.
- `localStorage` 접근 실패(사생활 보호 모드 등) 시 메모리로 동작하고 상단에 "저장되지 않습니다" 경고 배너.

### 4.9 날짜 전환 (FR-09, P2)
- 앱 진입 시 마지막 사용 날짜와 오늘 날짜를 비교.
- 날짜가 바뀌었고 미완료 항목이 있으면 "어제 못 끝낸 N개를 가져올까요?" 안내.
- 완료 항목은 날짜별 기록으로 보관(조회 기능은 이후 버전).

## 7. 데이터 모델

### 7.1 Todo

```ts
interface Todo {
  id: string;            // crypto.randomUUID()
  text: string;          // 1~100자
  completed: boolean;
  priority: 'high' | 'normal' | 'low';  // 기본 'normal' (P2)
  order: number;         // 정렬 순서 (드래그 정렬용)
  createdAt: string;     // ISO 8601
  completedAt: string | null;
}
```

### 7.2 저장 구조 (localStorage)

| Key | Value | 설명 |
|---|---|---|
| `todayTodo.v1.todos` | `Todo[]` (JSON) | 현재 할일 목록 |
| `todayTodo.v1.lastDate` | `"2026-11-02"` | 마지막 접속 날짜 (FR-09) |
| `todayTodo.v1.history` | `{ [date]: Todo[] }` | 지난 날짜 완료 기록 (P2) |
| `todayTodo.v1.theme` | `"light" \| "dark" \| "system"` | 테마 설정 (P2) |

- 키에 버전(`v1`)을 포함해 이후 스키마 변경 시 마이그레이션 가능하도록 한다.
- JSON 파싱 실패 시 빈 목록으로 시작하고 손상 데이터는 `*.corrupt` 키로 백업.

## 8. 기술 설계

### 8.1 파일 구조 (예정)

```
todolist/
├── prd.md          # 본 문서
├── index.html      # 마크업
├── style.css       # 스타일 (CSS 변수, 반응형, 다크모드)
└── app.js          # 상태 관리 + 렌더링 + 저장
```

### 8.2 아키텍처
단방향 데이터 흐름의 단순한 구조를 사용한다.

```
사용자 이벤트 → action(dispatch) → state 갱신 → storage 저장 → render()
```

- **state**: `{ todos, filter }` 단일 객체.
- **actions**: `addTodo`, `toggleTodo`, `editTodo`, `deleteTodo`, `undoDelete`, `clearCompleted`, `setFilter`, `reorder`.
- **storage**: `load()` / `save()` — try/catch로 감싸 실패 시 메모리 모드.
- **render**: state 기반으로 목록을 다시 그림. 이벤트는 목록 컨테이너에 **이벤트 위임**으로 등록.

### 8.3 모듈 책임

| 모듈 | 책임 |
|---|---|
| `storage` | localStorage 읽기/쓰기, 버전 키, 오류 처리 |
| `store` | state 보관, action 처리, 변경 시 구독자 호출 |
| `view` | DOM 렌더링, 진행률 계산·표시, 빈 상태 처리 |
| `controller` | DOM 이벤트 → action 연결, 키보드 단축키 |
| `dateUtil` | 오늘 날짜 문자열, 한국어 날짜 포맷, 날짜 변경 감지 |

### 8.4 키보드 단축키

| 키 | 동작 |
|---|---|
| `/` 또는 `N` | 입력창 포커스 |
| `Enter` | 추가 / 편집 저장 |
| `Esc` | 편집 취소 |
| `Space` (항목 포커스 시) | 완료 토글 |
| `Delete` (항목 포커스 시) | 삭제 |

## 11. 수용 기준 (Acceptance Criteria, MVP)

- [ ] 텍스트 입력 후 Enter 시 항목이 추가되고 입력창이 비워진다.
- [ ] 공백만 입력하면 항목이 추가되지 않는다.
- [ ] 체크박스 클릭 시 완료 스타일이 적용되고 진행률이 즉시 갱신된다.

- [ ] 새로고침 후에도 목록과 완료 상태가 그대로 유지된다.
- [ ] `<script>alert(1)</script>` 입력 시 문자열 그대로 표시된다.
- [ ] 360px 화면에서 가로 스크롤 없이 모든 기능을 사용할 수 있다.
- [ ] 할일이 없을 때 빈 상태 안내가 표시된다.

## 12. 퀘스트 보드 개편 (v0.2)

### 12.1 배경
게임의 퀘스트 창처럼 **단기 목표**와 **장기 목표(스토리 퀘스트)**를 나눠 보여 주는 방식을 연구 업무에 적용한다. 빠르게 처리할 일과 오래 붙잡고 연구할 주제가 한 목록에 섞이면, 장기 과제의 진척이 보이지 않고 단기 업무에 묻히기 때문이다.

### 12.2 컨셉
- **세계관:** 귀엽고 소박한 파스텔 동화 세계. 주인공들이 게시판에서 일을 "수주"해 노동하는 분위기.
  - 색감·말투·용어(노동, 수주, 풀뽑기, 토벌 등)로 분위기를 표현하고, v0.3부터 캐릭터 도트 팬아트를 보드 둘레에 배치한다 (§13).
  - 캐릭터 그림은 원작 이미지를 쓰지 않고 직접 찍은 24×24 도트 팬아트다. 원작 저작권이 있으므로 **개인 용도로만 쓰고 공개 배포하지 않는다.**
- **비주얼:** 도트(픽셀) 아트 — 계단식 모서리 박스, 칸 단위 진행률 바, 픽셀 체크박스, 문자 지도로 그린 SVG 도트 아이콘(새싹·깃발·별), 한글 도트 폰트 Galmuri.
- **화면 이름:** `노동 게시판` (QUEST BOARD)

### 12.3 퀘스트 종류

| 구분 | 화면 이름 | 용도 | 표시 방식 |
|---|---|---|---|
| 단기 퀘스트 (`daily`) | 오늘의 노동 🌱 | 오늘 안에 끝낼 수 있는 업무 (메일 회신, 데이터 정리 등) | 한 줄 체크리스트 + 오늘의 진행률 바 |
| 장기 퀘스트 (`story`) | 스토리 퀘스트 🚩 | 몇 주~몇 달 걸리는 연구 주제 | 카드 + 세부 목표 체크리스트 + 카드별 진행률 + 경과 일수 |

### 12.4 사용자 스토리 (추가)

| ID | 사용자 스토리 | 우선순위 |
|---|---|---|
| US-13 | 연구자로서 할일을 단기/장기 중 어디에 넣을지 골라 추가하고 싶다. | P0 |
| US-14 | 연구자로서 장기 퀘스트를 세부 목표로 쪼개고, 목표별로 체크하고 싶다. | P0 |
| US-15 | 연구자로서 장기 퀘스트의 진행률과 시작한 지 며칠째인지 보고 싶다. | P0 |
| US-16 | 연구자로서 끝낸 장기 퀘스트에 CLEAR 표시를 받고 싶다. | P0 |
| US-17 | 연구자로서 장기 퀘스트의 세부 목표를 오늘의 노동으로 끌어오고 싶다. | P2 |

### 12.5 데이터 모델 변경

```ts
interface Quest {          // 기존 Todo 확장
  id: string;
  type: 'daily' | 'story'; // 신규
  text: string;
  completed: boolean;
  steps: Step[];           // 신규 — story에서만 사용
  createdAt: string;       // story의 "N일째" 계산에 사용
  completedAt: string | null;
}

interface Step {
  id: string;
  text: string;            // 1~100자
  done: boolean;
}
```

- 저장 키는 `todayTodo.v1.todos`를 그대로 쓴다. `type`이 없는 MVP 데이터는 불러올 때 `daily`로, `steps`가 없으면 `[]`로 보정한다.
- 스토리 퀘스트 진행률 = 완료한 세부 목표 / 전체 세부 목표. 퀘스트를 완료 처리하면 100%로 표시한다.

### 12.6 화면 구성
- 넓은 화면(900px 이상): 왼쪽 `오늘의 노동`, 오른쪽 `스토리 퀘스트` 2단.
- 좁은 화면: 위아래 1단.
- 각 패널에 입력창과 `수주` 버튼이 따로 있다.
- 스토리 카드 하단의 `+ 세부 목표 추가` 입력창에서 Enter로 목표를 추가한다. 완료된 카드에는 입력창 대신 `CLEAR` 도장이 붙는다.
- 오늘의 노동을 모두 끝내면 "오늘의 노동 끝! 수고했어~"를 표시한다.
- 다크 모드에서는 밤 색감 팔레트로 바뀐다.

### 12.7 결정이 필요한 사항
1. 날짜가 바뀌면 완료한 단기 퀘스트를 자동으로 비울지 (스토리 퀘스트는 유지)
2. 세부 목표를 모두 끝내면 스토리 퀘스트를 자동으로 CLEAR 처리할지, 직접 완료 보고하게 할지
3. 보상 요소(경험치·코인 등)를 넣을지

## 13. 노동 난이도 & 캐릭터 (v0.3)

### 13.1 노동 난이도
단기 퀘스트(오늘의 노동)를 난이도로 나눈다.

| 값 | 이름 | 의미 | 표시 |
|---|---|---|---|
| `weed` | 풀뽑기 | 저난도 — 금방 끝나는 잡무 | 🌱 새싹 아이콘, 초록 태그 |
| `hunt` | 토벌 | 고난도 — 집중이 필요한 업무 | 🗡 검 아이콘, 분홍 태그 |

- 오늘의 노동 입력창 위의 토글에서 고른다. 기본값은 풀뽑기.
- 데이터: `Quest.difficulty?: 'weed' | 'hunt'` (단기 퀘스트에만). 값이 없는 기존 데이터는 `weed`로 보정한다.

### 13.2 캐릭터 링
보드가 캐릭터들에게 둘러싸인 느낌을 주기 위해, 보드를 감싼 무대(`#stage`)의 여백에 캐릭터 9명을 배치한다.

| 캐릭터 | 말버릇 |
|---|---|
| 치이카와 | 시러~ 시이러~~ |
| 하치와레 | 어떻게든 되어라~! |
| 우사기 | 우라 야하야하 |
| 갑옷씨 | 아이고~! |
| 시사 | 샤부넴! |
| 쿠리만주 | 키야아~~!!! |
| 모몽가 | 상냥하게 까서 내 입에 쏘옥 넣어라! |
| 카니 | 활짝~~ |
| 랏코 | (한정판 딸기 디저트가) 온다. |

- **배치:** 넓은 화면(700px 이상)은 위 3 · 오른쪽 2 · 아래 2 · 왼쪽 2로 시계 방향 링. 좁은 화면은 좌우 여백이 없으므로 위 5 · 아래 4.
  - 위·아래 줄은 보드 가장자리에 걸터앉되, 캐릭터마다 높낮이(`dy`)를 몇 픽셀씩 달리해 일직선으로 보이지 않게 한다.
  - 양옆 캐릭터는 보드 높이에 비례한 자리 대신 **옆 레일**에 선다. 레일 안 상자가 `position: sticky`라서 스크롤하면 화면을 따라 내려오고, 보드 끝에 닿으면 멈춘다. 할 일이 많아 보드가 길어져도 늘 화면 안에서 보드 옆에 붙어 있다. 레일 안에서도 좌우로 살짝씩(`dx`) 비켜 선다.
  - 넓은 화면(1000px 이상)은 여백을 넉넉히: 보드 둘레 여백 위 136 · 옆 128 · 아래 128px, 두 패널 사이 48px, 머리글 줄 사이 14~16px. 옆 레일 캐릭터는 위 줄보다 한참 아래(230px)에서 시작해 화면 높이의 30%씩 떨어져 선다.
- **그림:** 24×24 도트. `tools/sprites.py`가 타원(큰 머리·작은 몸·팔·발)을 쌓고 바깥 테두리를 자동으로 그려 문자 지도를 만들고, 그 결과를 `app.js`의 `pixel.ART`에 넣는다. 두 프레임으로 통통 뛰는 대기 모션, 캐릭터마다 박자가 조금씩 다르다.

### 13.3 말풍선 규칙
- 한 번에 **한 캐릭터만** 말한다. 직전과 다른 캐릭터를 무작위로 고른다.
- 말풍선은 **50초** 동안 유지되고, 50초가 지나면 그 말풍선이 사라지면서 다음 캐릭터가 말한다 (50초 주기, 늘 한 명이 말하는 중).
- 페이지를 열고 3초 뒤 첫 말풍선을 띄운다.
- 캐릭터·오브제를 클릭하면 그 말풍선이 바로 10초간 뜬다. 자동 순서와는 별개로 동작한다.
- 말풍선은 보드 바깥 여백 쪽으로 펼친다 (위·아래 줄은 좌우로, 옆 줄은 위로).
- 시간 값은 `app.js`의 `critters` 모듈 상단 상수(`SHOW_MS`, `CLICK_MS`, `FIRST_MS`)로 조정한다.
- 접근성: 말풍선은 스크린 리더에 반복해서 읽히지 않도록 숨기고, 캐릭터 버튼의 `aria-label`에 이름과 말버릇을 넣는다. `prefers-reduced-motion`이면 애니메이션을 끈다.

### 13.4 오브제 (하치와레 맞은편)
보드 아래 가운데(위 가운데 하치와레의 맞은편)에 먼작귀 세계관 오브제 4개가 번갈아 놓인다.

| 순서 | 오브제 | 상태에 따른 변화 | 클릭 대사 |
|---|---|---|---|
| 1 | 풀숲 | 오늘의 풀뽑기 중 남은 비율 > 50% 무성 → 그 이하 듬성 → 0개면 뽑은 풀 더미 | "풀뽑기 N개 남았어" / "풀 다 뽑았다!" |
| 2 | 노동 게시판 | 끝내지 않은 퀘스트 수만큼 공고 종이 (최대 4장) | "남은 노동 N건" / "오늘 일거리는 끝!" |
| 3 | 맥주 | 늘 가득 찬 잔 (잔 안 맥주 12줄 : 거품 3줄 = 4:1, 거품이 잔 위로 몽글몽글) | "노동이 끝나면 이 한 잔이 기다려요…" / 다 끝내면 "노동 뒤의 한 잔! 키야아~" |
| 4 | 라멘 | 김이 나는 라멘 (상태 무관) | "라멘 한 그릇 어때? 후루룩" |

- **교대 시점:** 캐릭터 말풍선이 새로 뜰 때마다 다음 오브제로 바뀌고, 다음 말풍선까지 그대로 유지된다 (첫 말풍선과 함께 등장 → 50초마다 교대).
- 퀘스트를 체크·추가·삭제하면 지금 놓인 오브제의 그림과 대사가 바로 갱신된다.
- 좁은 화면에서는 아래 줄 캐릭터를 10·30·70·90% 자리로 옮기고 가운데 50%를 오브제 자리로 비운다.
- 그림은 `tools/sprites.py`의 `weeds`, `board`, `beer`, `ramen` 함수가 만든다.

## 14. 일정 (v0.4)

### 14.1 오늘의 노동 — 마감
- 입력 폼에 `⏰ 마감` 날짜·시간 입력을 둔다. 둘 다 선택 사항.
  - 둘 다 비움 → 마감 없음 / 시간만 → 오늘 그 시간 / 날짜만 → 그날 하루 끝까지 / 둘 다 → 그날 그 시간.
  - 퀘스트를 수주하면 마감 입력은 비워진다. `✕`로 직접 비울 수도 있다.
- 퀘스트 옆 마감 태그:

| 상황 | 표시 |
|---|---|
| 오늘, 시간 있음 | `⏰ 오늘 15:00까지` |
| 오늘, 날짜만 | `⏰ 오늘까지` |
| 내일 | `⏰ 내일 09:00` / `⏰ 내일까지` |
| 그 뒤 | `⏰ D-3` (마우스를 올리면 정확한 날짜·시간) |
| 마감이 지났고 미완료 | `⏰ 마감 지남` (분홍 강조) |

- 화면은 1분마다 다시 그려 마감 상태를 갱신한다 (카드 안 입력창에 쓰는 중이면 건너뛴다).
- 데이터: `Quest.due: 'YYYY-MM-DD' | 'YYYY-MM-DDTHH:MM' | null` (단기 퀘스트만).

### 14.2 스토리 퀘스트 — 퀘스트 달력
- 스토리 퀘스트 패널에 접고 펼 수 있는 `📅 퀘스트 달력`(월 단위, 일요일 시작)을 둔다.
- 날짜를 누르면 그날 기록된 할 일을 모든 스토리 퀘스트에 걸쳐 보여 준다. 할 일마다 어느 퀘스트 것인지 색 태그가 붙는다.
- 아래 폼에서 진행 중인 스토리 퀘스트를 골라 그 날짜에 할 일(일정)을 기록한다.
- 달력의 일정 목록은 **보기 전용**이다. 체크칸이 없고, 완료 여부(`✓ 완료` / `오늘` / `지남` / `D-n`), 세부 퀘스트 진행, 메모 첫 줄을 보여 준다. 누르면 카드의 그 일정으로 이동해 펼친다.
- 달력 칸에는 그날 일정이 있는 퀘스트마다 **곰돌이 포셰트 얼굴**(14×12 도트, `tools/sprites.py`의 `bear_pochette`)을 앉힌다. 털색은 퀘스트 색이고, 여러 퀘스트면 최대 3마리가 겹쳐 앉는다. 날짜가 정해진 일정은 중요하므로 완료해도 곰돌이는 그대로 남는다.
- 퀘스트 색은 먼저 수주한 퀘스트부터 분홍(포셰트 원래 색)·파랑·초록·노랑·보라·주황 순.
- 스토리 퀘스트 카드에 `📅 일정 n/m` 체크리스트를 둔다. **일정 체크는 여기서만** 한다.
  - 모든 일정을 날짜순으로 보여 주고, 완료해도 사라지지 않는다 (줄만 긋고 `✓ 완료` 꼬리표).
  - 일정을 펼치면 그 아래에 **세부 퀘스트**(체크리스트, 추가·체크·삭제)와 **메모**(여러 줄, 최대 2000자)가 있다.
  - 메모는 타이핑하는 즉시 저장되고, 화면을 다시 그려도 쓰던 내용과 펼침 상태가 유지된다.
  - 일정 삭제는 실수로 지우지 않도록 두 번 눌러야 한다 (`일정 삭제` → `한 번 더 누르면 삭제돼요`, 3초 안에).
- 데이터: `Quest.schedule: { id, date: 'YYYY-MM-DD', text, done, steps: { id, text, done }[], memo: string }[]` (스토리 퀘스트만). 이전 데이터는 `steps: []`, `memo: ''`로 보정한다. 퀘스트를 지우면 일정도 함께 지워진다.
- 날짜는 로컬 시간 기준 `YYYY-MM-DD`로 다룬다 (UTC 변환으로 날짜가 밀리지 않도록).

| 업체명 | `company` | |
| 제품명 | `product` | |
| 세부사항 | `text` | 퀘스트 내용 그대로 |
| 담당 연구원 | `researcher` | 여러 명은 쉼표로 (엑셀에서는 줄바꿈) |

- 각 퀘스트에도 `📋 일지 정보 (n/7)`이 있어 펼쳐서 고칠 수 있다. 글자는 타이핑하는 즉시 저장되고, 퀘스트 이름 아래 `[구분] 업체명 · 제품명` 줄도 바로 바뀐다.
- 이전 데이터는 빈 값으로 보정한다.

### 15.2 엑셀 추출
- 머리글의 `📥 오늘 일지 엑셀로 받기` → `업무일지_YYYY-MM-DD.xlsx` (시트 이름도 날짜).
- 담기는 줄: 오늘의 노동 전부 + 진행 중이거나 오늘 끝낸 스토리 퀘스트. 스토리 퀘스트의 세부사항 아래에는 오늘 날짜 일정을 `· 할 일 (완료)`로 덧붙인다.
- 양식: 1행 회색 머리글(구분 칸은 비움), 구분별로 A열 세로 병합, 모든 칸 얇은 테두리·가운데 정렬·줄바꿈, 맑은 고딕 9pt, 1행 고정.
- 구분마다 원래 양식처럼 최소 줄 수를 그려 둔다 (14·3·5·2·4·4·6줄). 퀘스트가 더 많으면 그만큼 늘어난다. 구분이 없는 퀘스트는 맨 아래 `미분류`로 모은다.
- ExcelJS 4.4.0을 버튼을 누를 때만 CDN에서 불러온다. 평소에는 인터넷 없이 동작하고, 불러오지 못하면 안내 문구를 보여 준다.

## 16. 하루 단위 흐름 · 지난 기록 · 검색 (v0.6)

### 16.1 하루 단위 보드
- 어떤 날 D의 보드 = **D까지 수주했고, 아직 안 끝냈거나 D 이후에 끝낸 퀘스트** (`daybook.on`).
  - 그래서 오늘 못 끝낸 일만 내일로 넘어가고, 끝낸 일은 다음 날부터 보드에서 빠진다.
  - 스토리 퀘스트도 같은 규칙: 완료(CLEAR)한 날까지 보이고, 그 뒤에는 지난 기록과 검색으로 찾는다.
  - D 이후에 끝낸 퀘스트는 D의 보드에서 '진행 중'으로 보인다 (`daybook.asOf`).
- 전날에서 넘어온 단기 퀘스트에는 `↪ 11/1부터` 꼬리표를 붙인다.
- 데이터는 바꾸지 않는다. 날짜가 바뀌면 화면이 규칙대로 다시 그려질 뿐이다 (1분마다 갱신, 자정이 지나면 저절로 다음 날).
- 하단 오브제(풀숲·게시판·맥주)는 늘 오늘의 보드 기준이다.

### 16.2 다른 날짜 보기·적기 (v0.7)
- 머리글의 `◀ 날짜 ▶ 오늘`로 지난 날과 앞날 모두 이동할 수 있다.
- **어느 날짜에서든 수주·체크·편집할 수 있다.** 기록은 보고 있는 날짜를 따른다.
  - 수주: 그 날짜에 수주한 것으로 기록 (`createdAt` = 그날의 지금 시각). 지난 날 빠뜨린 일을 돌아가서 적거나, 앞날 할 일을 미리 적어 둔다.
  - 체크: 그 날짜에 끝낸 것으로 기록 (`completedAt` = 그날). 그날 화면에서 끝난 걸로 보이면 체크를 풀어 되돌린다.
  - 마감에서 시간만 고르면 보고 있는 날짜의 그 시간이 된다.
  - 앞날에 적은 일은 그날이 되기 전까지 오늘 보드에 나오지 않는다.
- 안내줄: 지난 날 `📖 … 여기서 적는 일은 이 날 수주한 것으로, 체크는 이 날 끝낸 것으로 기록돼요.` / 앞날 `🗓️ … 미리 적어 둔 일은 이 날부터 보드에 나타나요.` + `오늘로 돌아가기`.
- 오늘 보드의 오늘의 노동 아래에 `📅 앞으로 예정된 일 N건 · 11/5, 11/6 …` (오늘의 노동·스토리 퀘스트 모두). 누르면 가장 가까운 날로 이동한다.
- 스토리 퀘스트의 `N일째`는 보고 있는 날짜 기준이다.
- 한계: 세부 목표·일정 체크는 언제 했는지 기록하지 않으므로 어느 날짜에서 봐도 지금 상태로 보인다.
- 퀘스트 달력은 끝난 퀘스트의 일정까지 모두 보여 준다. 달력 일정을 누르면 그 퀘스트가 보이는 날로 이동한다.
- 엑셀 버튼은 `📥 이 날 일지 엑셀로 받기` — 보고 있는 날짜의 보드를 `업무일지_YYYY-MM-DD.xlsx`로 뽑는다.

### 16.3 업무 이력 검색
- 머리글의 검색창. 띄어쓰기로 나눈 낱말이 **모두** 들어 있는 퀘스트를 찾는다 (대소문자 무시).
- 검색 대상: 세부사항(퀘스트 내용), 구분, 업체명, 제품명, 담당 연구원, 담당 BM/영업, 품질보증 담당자, 비고, 세부 목표, 달력 일정, 일정 메모, 일정 세부 퀘스트.
- 결과(최근에 움직인 순, 최대 30건): 아이콘 + 퀘스트 내용, `진행 중` / `11월 1일 (일) 완료`, `[구분] 업체명 · 제품명 · 11/1 수주`, 내용이 아닌 칸에서 찾았으면 `업체명: …` 처럼 근거 한 줄. 찾은 낱말은 노란 형광펜.
- 결과를 누르면 그 퀘스트가 보이는 날(끝낸 날 / 앞날에 적은 일은 그날 / 그 밖에 진행 중이면 오늘)로 이동해 반짝여 보여 준다. 일정·메모에서 찾았으면 그 일정을 펼친다.
- `Esc`나 바깥을 누르면 결과를 닫는다.

## 17. 계절 테마 (v0.8)

> 이 버전부터 **데스크탑 전용**으로 개발한다 (휴대폰 화면은 더 다듬지 않는다).

### 17.1 테마 구조
- 머리글의 `🎨 테마` 버튼으로 고른다: `기본` / `🎄 크리스마스` (앞으로 차 마시는 테마 등 추가).
- `<html data-theme="…">`로 색 변수를 갈아 끼우고, 테마마다 장면(배경 그림)을 붙였다 뗀다 (`app.js`의 `theme`).
- 고른 테마는 이 브라우저의 `todayTodo.v1.theme`에 기억한다.
- 패널 안의 옅은 바탕은 `--paper` 변수로 페이지 배경(`--bg`)과 분리해, 배경이 짙은 테마에서도 패널 안은 밝게 유지한다.

### 17.2 🎄 크리스마스
- **색:** 키 컬러 빨강(`#c8323c`)·초록(`#2f7d4a`). 배경은 짙은 초록 밤하늘, 패널은 크림색. 수주·기록 버튼과 선택된 테마 버튼은 빨강, 오늘의 노동 머리는 연초록, 스토리 퀘스트 머리는 연분홍.
- **쌓인 눈:** 화면 맨 아래에 물결무늬 윗면(32×10 도트 무늬 반복)으로 소복이 쌓인 눈. 보드 뒤에 깔린다.
- **큰 트리:** 64×88 도트, 4단 트리에 금빛 갈랜드와 빨강·금·파랑·흰·은색 오너먼트를 빼곡히(겹치지 않게 자동 배치). 꼭대기에는 치이카와의 **별 세 개**(통통한 노란 별, 동그란 눈, 꽉 문 이빨)를 위 하나·아래 둘로 쌓는다.
- **선물 더미:** 72×30 도트, 빨강·초록·흰·금·파랑 상자 7개에 리본과 나비 매듭.
- 트리는 **창 높이를 꽉 채운다** (도트 한 칸 = `(100vh - 40px) / 88`). 화면 오른쪽에 서고, 밑동은 바닥에 쌓인 눈 속에 폭 박힌다 (쌓인 눈이 밑동 위를 덮는다). 선물 더미도 같은 칸 크기로 트리 아래 눈 위에 쌓인다. 장면은 보드 뒤에 깔려서 할 일은 가리지 않는다.
- **내리는 눈:** 동그란 픽셀 눈송이(5×5) 48개가 9~19초에 걸쳐 좌우로 살랑이며 떨어진다. 클릭은 그대로 통과하고, 움직임 줄이기 설정이면 내리지 않는다.
- 그림은 `tools/sprites.py`의 `chubby_star`, `star_trio`, `xmas_tree`, `xmas_gifts`, `snowflake`.

## 18. Neon DB 연결 · 여러 컴퓨터 (v0.9)

### 18.1 목표
- 회사·집 등 여러 컴퓨터에서 같은 데이터를 쓴다 → Vercel 에 올리고 Neon PostgreSQL 에 저장한다.
- 업무 정보(업체명 등)가 담기므로 **비밀번호 잠금**을 둔다.
- Neon 프로젝트 **TO DO LIST_CHIIKAWA**: `main` = 백지 템플릿(표 구조만), `FOR COMPANY TASK` = 실제 데이터. 백지로 돌아가기는 Neon 의 *Reset from parent*, 표 구조 변경은 마이그레이션 스크립트가 두 브랜치에 똑같이 적용한다 → "별개이면서 유기적".

### 18.2 구조
- `api/session.js` (GET 로그인 여부), `api/login.js` (POST 로그인 / DELETE 로그아웃), `api/quests.js` (GET 전체 / PUT 바뀐 것만).
- 로그인: `APP_PASSWORD` 와 비교(해시 후 일정 시간 비교, 틀리면 0.6초 지연) → `만료시각.HMAC서명` 쿠키(`HttpOnly`, `SameSite=Lax`, https 면 `Secure`, 30일). 쓰는 요청은 `application/json` 만 받는다.
- 표 `quests (id text PK, data jsonb, created_at, updated_at, deleted_at)` — 퀘스트 한 개 = 한 줄. 지우면 `deleted_at` 만 찍는다(되살릴 수 있게).
- 마이그레이션: `db/migrations/NNN_*.sql` + `db/migrate.mjs` (두 브랜치, `schema_migrations` 로 적용 기록, 템플릿에 데이터가 있으면 경고). 백업: `db/backup.mjs`.
- 로컬 개발: `dev-server.mjs` (`npm run dev`, 포트 8126) 가 Vercel 과 같은 화면 파일 + `api/` 를 돌린다. 화면 파일 외(.env·db·tools·prd)는 내주지 않는다.
- Vercel 에는 `.vercelignore` 로 `prd.md`·`tools/`·`db/`·`.env`·`dev-server.mjs` 를 빼고 올린다.

### 18.3 앱의 동기화 (`app.js` 의 `sync`)
- 시작할 때 `/api/session` 이 있으면 **DB 모드**, 없으면(python http.server) 예전처럼 **브라우저 저장 모드**.
- DB 모드: 로그인 문 → 불러오기 → `store.replaceAll()`. 이후 저장할 때마다(`storage.onSave`) 0.7초 모았다가, 서버에 마지막으로 저장된 모습과 **달라진 퀘스트만** 보낸다(400개씩). 실패하면 점점 길게 기다리며 다시 시도.
- 다른 컴퓨터의 변경: 창으로 돌아올 때와 90초마다 가져온다 (보내지 못한 변경이 있으면 먼저 보낸 뒤).
- 머리글에 `☁️ 저장됨 / 저장 중… / ⚠ 저장 실패` 와 로그아웃. 로그아웃하면 화면과 브라우저 사본의 업무 데이터를 지운다 (DB 는 그대로).
- 처음 DB 에 연결할 때 DB 가 비어 있고 이 브라우저에 퀘스트가 있으면 올릴지 묻는다. 올리지 않으면 브라우저 쪽은 `todayTodo.v1.todos.local-backup` 에 따로 보관한다.
- 테마 선택은 지금처럼 브라우저마다 따로 기억한다.
